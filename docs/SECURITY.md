# Приватность и безопасность

## Какие данные сохраняются

Проекты могут содержать рисунки, описания, истории, геометрию и текстуры. Каталог generations содержит отправленный рисунок, запрос, ответ и журналы CLI; backups — копии проектов. Считайте эти каталоги личными данными. По умолчанию они находятся вне checkout. Не указывайте каталог данных внутри публикуемого репозитория.

Обычная работа не передаёт проекты по сети. Генерация — отдельное действие с явным согласием: выбранный рисунок и текст отправляются через установленный Codex CLI. Его аутентификация остаётся в собственном хранилище CLI. Приложение не копирует её в проект и удаляет OPENAI_API_KEY/CODEX_API_KEY из окружения дочернего процесса.

Генерация запускается без оболочки, с отключёнными пользовательскими конфигурациями, плагинами, поиском, shell-tool и подагентами, в read-only режиме. Это ограничение области работы, а не основание передавать чужие секреты в рисунке или описании. Полученный JSON проверяется до применения.

## Локальный сервер

Сервер привязан к 127.0.0.1. Host и Origin проверяются, CORS не открывается внешним сайтам. CSP запрещает внешние скрипты и встраивание страницы; ответы имеют nosniff. Тексты проекта вставляются через textContent/поля формы. Не публикуйте сервер через прокси и не меняйте bind на 0.0.0.0: для публичного хостинга нужны отдельные меры аутентификации и изоляции.

Импортируемые ZIP читаются в памяти с пределами размеров. Пути выхода за каталог, обратные слеши, неоднозначные имена и дубликаты отклоняются. Код из архивов при объединении не выполняется. Игровые действия представлены декларативными блоками, произвольного eval команд проекта нет. В Node-тестах доверенный исходник игровых адаптеров загружается с подменами API; пользовательские данные туда не передаются.

## Перед публикацией

Публикуйте только исходники, собственную документацию и материалы с подходящей лицензией. Не добавляйте каталоги данных, дампы окружения, журналы CLI, ключи, токены и чужие рисунки. Gitignore помогает не добавить их случайно, но не очищает уже существующую историю Git.

Выполните проверки из [инструкции разработчика](DEVELOPMENT.md). Если настоящий ключ был опубликован, удаление файла не отменяет доступ: ключ нужно отозвать у провайдера. В сообщениях об ошибках не прикладывайте личные проекты и полные журналы без проверки содержимого.
