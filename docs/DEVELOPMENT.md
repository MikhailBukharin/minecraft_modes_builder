# Разработка и проверка

## Среда

Python 3.10+ и Node.js 22+. Runtime использует стандартную библиотеку Python, frontend — обычные ES modules. Node нужен для тестов и форматирования, не для запуска приложения.

```sh
python -B -m unittest discover -s app -v
node app/check.mjs
python -B tools/check_public.py
```

Python проверяет генератор, архивы, графы, подменённый CLI, HTTP, изоляцию хранилища и атомарную запись. Node проверяет модели, масштаб игрока, обе ветки историй, отмену движения, инвентарь, откат сделки, нативные метаданные наград и индивидуальные/общие ограничения появления. Вызовов Codex или Minecraft в этих тестах нет. Браузерный предпросмотр не заменяет проверку пакета движком.

## Стиль

Придерживайтесь небольших функций и существующего разделения ответственности. Не добавляйте framework, сборщик или хранилище без необходимости. Общую игровую логику держите в независимых JS-модулях, а обращения к Bedrock API — в адаптерах. Вендорные файлы не форматируйте.

Необязательные инструменты разработчика:

```sh
python -m pip install -r requirements-dev.txt
python -m ruff check app tools
python -m ruff format --check app tools
npm --prefix app ci
npm --prefix app run format:check
```

Для применения стиля: `python -m ruff format app tools` и `npm --prefix app run format`. В package-lock.json зафиксирована версия Prettier; Ruff закреплён в requirements-dev.txt. В workflow настроены проверки Linux и Windows.

## Поиск секретов

```sh
python -B tools/check_secrets.py
```

Просмотрите каждую находку: длинная техническая строка может быть ложным срабатыванием, а автоматическая проверка не доказывает отсутствие любой личной информации. Не добавляйте реальный секрет в allowlist. Сканируйте подготовленный набор файлов, а при повторной публикации — также историю Git. Инструмент публикации дополнительно проверяет структуру, локальные профили пользователей и относительные ссылки Markdown без сетевых запросов.

## Изменения формата

Старые поля обновляет stories.upgrade. Сохранение черновика и экспорт имеют разные требования к полноте графа. Сохраните совместимость JSON либо добавьте явную миграцию. Для изменений экспортируемых путей проверьте как индивидуальную, так и общую сборку. Новую проверку добавляйте для границы, ошибки или поведения; не дублируйте реализацию тестом.

Документируйте подтверждённые проверки отдельно от планируемых. Пока игровой запуск и Realms не выполнены, не заменяйте это утверждением о совместимости в игре.
