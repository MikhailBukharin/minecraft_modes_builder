# Архитектура

Приложение состоит из Python-сервера стандартной библиотеки и браузерных ES modules. Framework, база данных и frontend-сборка не нужны. Three.js хранится локально. Исполнитель историй и логика инвентаря используются и в браузерных проверках, и в экспортируемых скриптах Bedrock.

| Модуль                         | Ответственность                                                                            |
| ------------------------------ | ------------------------------------------------------------------------------------------ |
| app/paths.py                   | Расположение исходников и отдельного пользовательского хранилища; импорт ничего не создаёт |
| app/storage.py                 | Атомарная замена сохранений, архивов и состояния генерации                                 |
| app/server.py                  | Loopback HTTP, проверки Host/Origin, API, выдача web и exports                             |
| app/bedrock.py                 | Проект по умолчанию, проверка геометрии, PNG и упаковка BP/RP                              |
| app/stories.py                 | Миграция старых полей, проверка графа, нативные группы движения                            |
| app/generation.py              | Необязательный Codex CLI, согласие, отмена, схема и проверка кандидата                     |
| app/texture_tools.py           | Палитра и одинаковая текстура для просмотра/экспорта                                       |
| app/rewards.py, npc_trading.py | Добыча, настройки магазина и нативные награды                                              |
| app/population.py              | Правила появления и оценка нагрузки                                                        |
| app/bundle.py                  | Проверка источников, переименование, согласование ресурсов и общая сборка                  |
| app/runtime.js                 | Игровое меню и запуск историй; остальные runtime-модули отвечают за отдельные механики     |
| app/web                        | Формы, холст, 3D, редактор модели и проверяемые общие функции                              |

## Потоки данных

Форма → JSON проекта → валидатор → предпросмотр/сохранение/экспорт. Геометрия, текстура и граф проходят проверку до сборки. Черновой граф можно сохранить; экспорт требует завершённого графа. Генерация сохраняет отдельного кандидата и не заменяет проект до подтверждения применения.

Общая сборка → загрузка источников → уникальные ID и пути → проверка ссылок → отпечаток исходников и подготовленных файлов → согласованная пара BP/RP. Перед записью отпечаток сверяется заново. Скрипты типов находятся в отдельных каталогах, чтобы конфигурации не перекрывались.

## Хранилище

В каталоге пользовательских данных находятся projects, exports, imports, bundles, generations и backups. Проекты хранятся JSON, архивы — ZIP-форматами Minecraft; секреты и данные входа не являются полями проекта. Старые данные из корня checkout не перемещаются автоматически: остановите сервер, сохраните копию и перенесите их в выбранное хранилище.

## HTTP API

GET: `/api/new`, `/api/projects`, `/api/project/{uuid}`, `/api/generation/provider`, `/api/generation/latest/{uuid}`, `/api/generation/jobs/{uuid}`, `/api/bundle/new`, `/api/bundle/sources`, `/api/bundles`, `/api/bundle/{uuid}`.

POST с JSON: `/api/save`, `/api/preview`, `/api/export`, `/api/model-backup`, `/api/guardrails`, `/api/generation/start`, `/api/generation/cancel`, `/api/bundle/import`, `/api/bundle/check`, `/api/bundle/export`.

POST требует локальный Host и Origin, тело ограничено 25 МБ. Для файлов и JSON установлены отдельные пределы. Статика ограничена web и exports; пользовательские проекты напрямую не выдаются. Повреждённые черновики пропускаются в списке, а не ломают открытие редактора. [Безопасность](SECURITY.md).
